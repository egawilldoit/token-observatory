# Token Observatory V1 architecture

## Invariant

A ccusage upload is an **absolute observation**, never a delta. The dashboard
must never add a new JSON snapshot on top of an older snapshot for the same
machine, agent and day.

Calendar truth comes from the latest successfully processed observation for:

```
machine × agent × usage_date
```

Weekly, monthly and lifetime totals are derived from that current daily view.

## V1 flow

1. User selects a registered machine.
2. User uploads a JSON generated by the pinned ccusage command.
3. Server computes SHA-256 before parsing.
4. Same-machine exact file matches are recorded as `exact_duplicate` and stop.
5. Raw non-duplicate files are stored immutably in the private `raw-imports` bucket.
6. Parser normalizes nested `agents[]` into daily agent rows.
7. Each row receives a deterministic usage hash that excludes cost.
8. Rows are classified as new, revised or unchanged against `v_current_daily_usage`.
9. One Postgres RPC inserts new/revised observations and marks the import processed.
10. The dashboard reads only `v_current_daily_usage`.

## Overlap collection

Normal collection uses a three-calendar-day overlap. If the newest accepted day is
2026-08-28, the next suggested command starts at 2026-08-26. Because row hashes are
idempotent, unchanged overlap days are skipped and revised late-arriving usage is
versioned safely.

A full-history reconciliation should still be run periodically (for example monthly)
because a short overlap is a practical safety margin, not proof that older upstream
history can never change.

## Cost

`reported_cost_usd` is informational ccusage output. Usage identity deliberately
excludes cost because pricing can change while token usage does not. V1 does not
pretend that ccusage estimated cost is an invoice.

## Security

Browser clients do not read or write telemetry tables. Authenticated pages call
Next.js server routes/components; server-only code uses a Supabase secret/service
key. Telemetry tables have RLS enabled with no anon/authenticated policies and their
Data API grants are revoked.

## Deferred

Sessions, projects, canonical model mapping, pricing provenance, and cross-machine
mirror/fork resolution are intentionally deferred. Raw `--breakdown` exports are
preserved so these dimensions can be backfilled later.
