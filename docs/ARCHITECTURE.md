# Token Observatory V1 architecture

## Core invariant

A ccusage upload is an **absolute observation**, never a delta. A newer snapshot
must never be added on top of an older snapshot for the same machine, agent, and
calendar day.

Calendar truth comes from the latest successfully processed observation for:

```
machine × agent × usage_date
```

Weekly, monthly, and lifetime totals are derived from that current daily view.

## Ingestion flow

1. The authenticated account must also be present in
   `TOKEN_OBSERVATORY_ALLOWED_EMAILS`.
2. The user selects a registered machine.
3. The user uploads JSON generated by the pinned ccusage command.
4. The server computes SHA-256 before parsing.
5. If those exact raw bytes are already processing or processed for the same
   machine, the attempt is recorded as `exact_duplicate` and is not promoted
   again. An exact hash seen on another machine is flagged as provenance evidence,
   but is not assumed to represent the same underlying usage event.
6. Stale `processing` imports older than 15 minutes are failed before claiming
   new work.
7. A database partial unique index permits only one active processing import per
   machine, preventing concurrent snapshots from racing "latest wins".
8. Raw non-duplicate files are stored immutably in private `raw-imports` Storage.
9. The parser normalizes nested `agents[]` into daily rows, validates real
   calendar dates, and requires agent totals to reconcile with the day's reported
   total.
10. Each row receives a deterministic usage hash that excludes cost.
11. Rows are classified as new, revised, or unchanged against
    `v_current_daily_usage`.
12. One Postgres RPC inserts new/revised observations and marks the import
    processed atomically.
13. The dashboard reads only `v_current_daily_usage`.

## Overlap collection

Normal collection uses a three-calendar-day overlap. If the newest accepted day is
2026-08-28, the next suggested command starts at 2026-08-26. Row hashes make
unchanged overlap idempotent while revised late-arriving usage receives a new
observation version.

A full-history reconciliation should still be run periodically because a short
overlap is a practical safety margin, not proof that older upstream history can
never change.

## Exact duplicates vs mirrors

SHA-256 equality proves byte identity, not event identity. It is therefore a hard
duplicate only within the same registered machine. Across machines it is recorded
as a warning because two independent machines can legitimately produce identical
exports.

V1 does **not** attempt semantic cross-machine mirror/fork resolution. Stable
machine identity remains part of canonical truth.

## Cost

`reported_cost_usd` is informational ccusage output. Usage identity deliberately
excludes cost because pricing can change while token usage does not. V1 does not
treat ccusage estimated cost as an invoice.

## Security

Browser clients never receive the Supabase secret/service-role key and do not read
or write telemetry tables directly. Authenticated identity is necessary but not
sufficient: telemetry routes and pages also enforce the explicit email allowlist
before server-only code uses privileged Supabase access.

Telemetry tables have RLS enabled with no anon/authenticated policies and their
Data API grants are revoked. The current-data view uses `security_invoker=true`.

The auth confirmation route only accepts application-local redirect paths to avoid
an open redirect.

## Failure behavior

- Invalid JSON, impossible dates, malformed token counts, missing agent identity, or
  agent/day reconciliation failures are rejected before DB promotion.
- Same-machine exact duplicate raw datasets are audit-recorded but never promoted twice.
- Same-machine concurrency is rejected with HTTP 409.
- Stale processing rows are recovered as failed.
- Storage or database-promotion failures mark the import failed; failed imports are
  never part of the canonical current-data view.

## Deferred

Sessions, projects, canonical model mapping, pricing provenance, and semantic
cross-machine mirror/fork detection for non-identical exports are intentionally
deferred. Raw `--breakdown` exports are preserved so these dimensions can be
backfilled later.
